## 1. Project Overview

**Merch From** is a conversational commerce platform that empowers artists, bands, and creators to manage their merchandise business through natural AI-powered conversation. **Mission:** Help artists, brands, and companies design, source, and sell premium quality merchandise through an AI-managed platform with professional visual tools.

**Core Values:** Vegan, fair-trade, eco-friendly products with premium quality focus, direct in-house production, and no upfront costs for qualified creators.

## 8. Production Automation System

### Purpose
Automate production workflows to reduce manual intervention while maintaining premium quality standards.

### AI Artwork Validation System
**Expert Panel Integration**
- Expert A (Brazil) - 15+ years, 6,600+ students trained
- Expert B (Brazil) - 40+ years industry legend
- Expert C (Brazil) - Market's best for quality

**Scoring Workflow**
- Expert rates each design 0.5-5 across 4 criteria:
  - Print Feasibility (1-5)
  - Color Accuracy (1-5)
  - Detail Preservation (1-5)
  - Commercial Viability (1-5)

**Automated Pre-Scoring**
- AI pre-scores designs before manual review
- Failed designs routed to human designer
- Low scores trigger "Francisca suggests edits" flow

**Human-in-the-Loop Routing**
- User frustration detected → "Ask a Human Designer" option
- AI suggests edits → Francisca provides alternatives
- Failed designs → Anonymous data collection for training improvement

**Quality Standards**
- Pre-press inspection: Mesh counts, solid coverage, no finger marks
- Post-press QC: Color accuracy testing
- Print approval thresholds: Minimum scores required

### File Management System
**OpenCV Format Requirements**
- CSV or Excel format for design files
- Metadata requirements: Designer name, design type, size, colors
- Version control naming: PROD_v1.0, PROD_v2.0

**Automated Upload to Cloudinary**
- Image optimization: WebP, AVIF, auto-format
- Asset organization: `/avatars/[character]/[expression]`
- CDN delivery: Global edge caching

**Print File Export System**
- Formats: DTF, screen films (large format positives), PDFs
- File naming: Job number + customer identifier
- Backup strategy: Local + Cloudinary
- Format specifications per print method

### Color Separation Automation
**Magna IM6 System**
- 15,000+ Pantone codes in database
- Automated micro-registration: ±1% tolerance for complex jobs
- 8-color registration for basic designs
- Spot color matching system
- Color proofing before production runs

### Print Queue Management
- Job prioritization: Based on complexity and deadline
- Workflow coordination: Single shirt → 8-color → DTG/DTG → Plotters → Curing
- Tracking dashboard: Real-time job status
- Completion estimation: Historical data averages

### Quality Control Workflow
- Expert panel QA: Monthly inspections of sample production runs
- Pre-press standards: Mesh count verification, color accuracy
- Print quality acceptance: Solid coverage, no finger marks
- Customer quality tracking system

### Equipment Maintenance Philosophy
- Preventive maintenance schedules for all equipment
- Calibration workflows for accuracy and consistency
- Equipment replacement planning
- Spare parts inventory system

## 11. Notification Strategy

### Architecture
**Two-Tier System**: In-App Notification Center (Primary) + Device Push Notifications (Sporadic)

### Tier 1: In-App Notification Center (Primary)
**Purpose**: Persistent, searchable notification history for operational communications

**Categories**
- Orders & Payments (production, fulfillment)
- Production & Fulfillment
- Shipping & Delivery
- Support Tickets (troubleshooting, issues)
- Test Print Approvals (bulk orders)
- Catalog Updates
- Community & Announcements

**Notification Types**
- **Rich Messages**: Text cards, product carousels, action buttons, images
- **Status Updates**: Clustered notifications (e.g., "New Orders (5)", "New Shipments (3)")
- **Alerts System**: Priority-based with color coding
  - Urgent (Red): Production issues requiring immediate attention
  - Standard (Blue): Order updates, shipping confirmations
  - Informational (Gray): Platform announcements, new features

**Features**
- Searchable history: 90-day retention
- Persistent storage: No data loss on session change
- Notification batching: Prevent fatigue
- Priority badging: Visual urgency indicators
- Snooze & batch capabilities: User controls notification frequency

### Tier 2: Device Push Notifications (Sporadic)

**Purpose**: Time-sensitive critical issues only

**Use Cases**
- Production issues requiring immediate attention
- Platform-wide major announcements
- System-wide maintenance (scheduled, emergency, etc.)
- Time-sensitive approval requests

**Frequency**: Very Low
- Examples: Equipment failure, payment provider issues, new security vulnerability

**Channels**
- Apple APNs (iOS) and Android
- Browser Push API (Web Push Protocol)
- Local push notification server (Phase 4+)

**Design Considerations**
- Sparse to prevent notification fatigue
- No spam or marketing abuse
- Rich but not overwhelming

## 16. Development Philosophy

### Core Principles
- **Build Once, Deploy Everywhere**: One codebase architected for production, with environment flags switching between demo/production
- **Avoid Over-Engineering for MVP Phases**: Every line of code written for demo is production-ready
- **Data-Driven Decisions**: Decisions based on metrics, not intuition
- **Use Managed Services**: Neon (database), Clerk (auth), Stripe (payments) vs. custom solutions
- **Incremental Delivery**: Ship imperfect features fast over perfect features slow
- **Balance Speed with Quality**: Early is better than never

### Quality Standards
- **Test in Production Before Shipping**: Real user feedback drives quality
- **Monitor Customer Satisfaction**: NPS scores, support ticket trends
- **Zero-Defect Culture**: Rejection threshold is real, quality is non-negotiable
- **Fail-Fast, Learn-Faster**: Ship features, measure, iterate quickly

### Architecture Principles
- **Monorepo Structure**: Single repository for efficiency, shared code
- **Clean Separation of Concerns**: Frontend (mainpage, app), Backend (Neon), Shared (db, lib)
- **Single Database Simplicity**: One PostgreSQL instance for all projects
- **Serverless-First**: Neon serverless for bootstrap-friendly, auto-scaling
- **API Routes**: Vercel Functions for backend logic

### Team Coordination
- **Clear Responsibilities**: Frontend vs. Backend vs. Design
- **Regular Sync Meetings**: Weekly standups, bi-weekly deep dives
- **Code Review Processes**: All PRs reviewed before merge
- **Async Communication**: GitHub issues, project management tools
- **Documentation Hygiene**: Update PRD, Roadmap, and docs in real-time

|-------|----------------|--------|

CREATE TABLE profit_sharing_contributors (

);

CREATE TABLE profit_sharing_distributions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  total_pool DECIMAL(10,2) NOT NULL,
  contributor_count INTEGER NOT NULL,
  per_contributor_amount DECIMAL(10,2) NOT NULL,
  status TEXT CHECK (status IN ('calculated', 'approved', 'transferred')),
  approved_by UUID REFERENCES user_profiles(id),
  transfer_reference TEXT, -- SEPA batch reference
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE profit_sharing_payouts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  distribution_id UUID REFERENCES profit_sharing_distributions(id),
  contributor_id UUID REFERENCES profit_sharing_contributors(id),
  amount DECIMAL(10,2) NOT NULL,
  transfer_status TEXT DEFAULT 'pending',
  transfer_date TIMESTAMPTZ,
  sepa_reference TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
